Architecture 2.1 Vue d'ensemble Application monolithique MVC : le navigateur appelle des routes Laravel ; les contrôleurs valident, autorisent, appellent des services métier puis renvoient des vues Blade. Une seule base MySQL. Navigateur (mobile / ordinateur) │ HTTP ▼ Routes ( web.php ) ── Middleware ( auth , rôle, langue) │ ▼ Contrôleurs ── FormRequests (validation) ── Policies (autorisation) │ ▼ Services métier (logique) ── Modèles Eloquent ── MySQL │ ▼ Vues Blade + Tailwind ◄ ── fichiers de traduction ( fr / en) 2.2 Responsabilités par couche Routes : regroupées par rôle ( public , expediteur , groupeur , admin ) avec préfixes et noms explicites. FormRequests : toute validation de formulaire y vit, jamais dans le contrôleur. Policies : qui peut voir, modifier, annuler quoi (ex. un groupeur ne modifie que ses trajets). Services : logique métier réutilisable (calcul de capacité restante, transitions de statut, mise à jour de la note moyenne). Contrôleurs : fins ; ils orchestrent seulement. Modèles : relations, « scopes » de requête, conversions de types ( casts ). 2.3 Structure des dossiers (extraits) app/ Enums / Role , GroupeurStatus , TripStatus , RequestStatus Http/ Controllers / Public/, Expediteur /, Groupeur/, Admin/ Middleware/ EnsureRole , EnsureGroupeurValidated , SetLocale Requests / un FormRequest par formulaire Models / User, GroupeurProfile , Trip, ShipmentRequest , ShipmentStatusHistory , Review , Report Notifications/ RequestReceived , RequestAnswered , StatusChanged , GroupeurValidated Policies / TripPolicy , ShipmentRequestPolicy , ReviewPolicy Services/ TripCapacityService , ShipmentWorkflowService , RatingService database / migrations/ seeders/ factories / lang / fr / en/ resources / views / layouts /, components/, public/, expediteur /, groupeur/, admin/ tests/ Feature / un fichier par parcours critique docs/ les 6 documents GPsen (référence pour Cursor ) 3. Règles métier techniques Capacité restante = capacité du trajet − somme des poids des demandes au statut acceptée , collectée , en transit ou livrée . Calculée dans TripCapacityService , jamais saisie à la main. Transitions de statut autorisées (service ShipmentWorkflowService ) : en_attente → acceptee | refusee | annulee , acceptee → collectee | annulee , collectee → en_transit , en_transit → livree . Toute autre transition est rejetée. Chaque transition écrit une ligne d'historique et déclenche une notification. Acceptation atomique : l'acceptation d'une demande s'exécute dans une transaction avec vérification de la capacité restante (verrouillage de la ligne du trajet) pour éviter le surbooking. Groupeur non validé : le middleware EnsureGroupeurValidated bloque la publication de trajet ; le compte voit un écran « validation en cours ». Avis : autorisé uniquement si la demande est livrée et que l'auteur est l'une des deux parties ; unicité sur (demande, auteur). La note moyenne du groupeur est recalculée dans RatingService . Contact WhatsApp : le lien https://wa.me/&lt;numéro international sans + &gt;? text =&lt;message encodé&gt; n'est rendu que si la demande est acceptée ou au-delà (voir le PRD, §5). Trajet passé : une tâche planifiée (ou un scope de requête) exclut des listes publiques les trajets dont la date de départ est dépassée. 4. Internationalisation Langues du MVP : français (par défaut) et anglais. Toutes les chaînes visibles passent par __('clé') et les fichiers lang / fr et lang /en . La langue choisie via le sélecteur (en haut à gauche) est enregistrée en session et, si l'utilisateur est connecté, dans users.locale . Un middleware SetLocale l'applique à chaque requête. Dates affichées avec Carbon localisé ; devise affichée en FCFA. 6. Performance et données Pagination (10 à 15 éléments) sur toutes les listes. Chargement anticipé ( with ( ) ) des relations pour éviter les requêtes N+1. Index sur : trips( status, departure_date ) , trips( origin_city , destination_city ) , shipment_ requests ( trip_id , status) , shipment_requests ( expediteur_id ) . Images : optimiser la photo d'arrière-plan ( WebP , poids raisonnable) ; chargement différé des images secondaires. Mise en cache de configuration et de routes uniquement en production. 7. Stratégie de tests Tests de fonctionnalité (Pest ou PHPUnit ) sur les parcours critiques, avec une base de test réinitialisée : Inscription expéditeur et inscription groupeur (compte « en attente »). Un groupeur non validé ne peut pas publier ; un groupeur validé le peut. L'admin valide un groupeur et celui-ci est notifié. Une demande d'envoi ne peut pas dépasser la capacité restante. L'acceptation met à jour la capacité ; le trajet passe à « complet » à zéro. Les transitions de statut interdites sont rejetées. Un utilisateur ne peut pas modifier le trajet ou la demande d'un autre. Un avis n'est possible que sur une demande livrée, une seule fois. Le lien WhatsApp n'est pas visible avant acceptation. Objectif réaliste avant la soutenance : ces neuf tests au vert. 8. Conventions de code Langue : code, tables et colonnes en anglais ; textes affichés en français/anglais via les fichiers de langue. (Les termes métier français du mémoire sont mappés dans le document Backend Schema .) Nommage : modèles au singulier ( Trip ), tables au pluriel ( trips ), contrôleurs TripController , routes nommées groupeur.trips .create . Un FormRequest par formulaire, une Policy par ressource sensible. Enums PHP pour les statuts et rôles, jamais de chaînes magiques dispersées. Pas de logique métier dans les vues Blade. Composants Blade réutilisables ( &lt;x-button&gt; , &lt;x-trip-card&gt; , &lt;x-status-badge&gt; ). Git : une branche par fonctionnalité ( feature /trips- crud ), commits courts à l'impératif, fusion dans main uniquement quand les tests passent. Formatage : Laravel Pint avant chaque commit. 9. Utilisation avec l'assistant de code Placer les six documents dans docs/ à la racine du projet et les référencer dans chaque demande (ex. : « lis docs/02-TRD.md et docs/05-Backend-Schema.md puis crée les migrations »). Un seul module par demande ; vérifier, tester, valider, puis passer au suivant. Demander à l'assistant de ne pas ajouter de dépendance non listée au §1 sans accord. En cas de conflit entre un document et une suggestion de l'assistant, le document fait foi. 11.
